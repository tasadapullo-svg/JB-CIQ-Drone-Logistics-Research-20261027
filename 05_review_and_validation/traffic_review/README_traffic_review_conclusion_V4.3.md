## E02 几何代理如何计算（不可写成真实路网）

1. 仅将G1中可由ID解析的观测链分成R1A、R1B、R2A、R2B四个顺序。R2中`RA206`无法可靠归入任一A/B序列，单列在未连通清单中，不强行插入。
2. 观测点相邻距离是WGS84大地线距离；这只为真实道路路径长度提供几何参考，**不是实际道路边长**。
3. 仅当两个端点有正观测速度时计算相邻段代理耗时（暂假定 km/h）：

   `t_proxy_minutes = 60 × (distance_km / 2) × (1/v_start + 1/v_end)`

   此法使用端点速度的调和平均数。结果是**代理估计**，并非真实耗时的严格上下界，因为观测段长、速度代表性和通关等待时间均未知。
4. 每条样本链计算3672个小时的端点到端点代理结果；另外针对预设08:00、12:00、17:00和20:00输出点对代理矩阵。不可将跨链或跨国点对当成已知连通。
5. 路段实际单行/双行、路口转弯、桥梁匝道、CIQ等待、道路拓扑、国境位置均**尚未验证**。所以不得用于RQ2门到门节时结论，也不得用于碳排放/车辆里程比较。

独立复读五份原始CSV，逐行比对修正版的节点ID、原始速度（绝对误差≤1e-6）、来源冻结分组及从时间戳推算的星期：

- **1,266,840条全量逐行比对：关键字段不一致数全部为0。**
- **全部41个相邻样本点几何段长度>0。**
- **全部14,688条点序列小时代理记录符合正值、缺失传播规则。**
- 41条连接中**14条涉及至少一端道路名称匹配证据`REJECTED`/`UNMATCHED`**，故不能视为可信、合法的可通行道路边。
- 这些成功项只证明**数据处理和计算程序的逻辑一致**，不证明外部道路拓扑、真实路段旅行时间或商业交通产品准确性。

## 正式E02的必要补充资料与验收条件

1. 取得带 `way_id / directed_from / directed_to / line_geometry / length_m / highway / oneway / access / turn_restriction` 的 Johor 地区可路由道路矢量层（例如经归档的OpenStreetMap PBF），注明采集日期、许可证及版本。
2. 将345个FCD查询点匹配至道路边，保存匹配距离、路名、方向及不确定性；对曾被列为 `REJECTED/UNMATCHED` 的点逐项处理，不能默默放行。
3. 只使用经证实位于马来西亚侧的候选仓储、微型站点和实际配送接收点；每个OD应具备 `origin_id, destination_id, location, access_point, task_type, release_time`。
4. 在同一小时的有向路网计算最短行车时间，保留道路长度、每条边使用的交通速度来源、未观测边的处理方法、行程时间与等待/停车/清关时间的独立成分。
5. 以可独立查证的历史导航旅行时间或现场样本复核模型误差；未经校准的GIS估算需标注为基于观测驱动的估计，不得称现场实测。
6. 冻结输入后一次性生成5个月OD时间矩阵与交通逻辑检查表，再进入RQ2无人机比较。不得依据想要的节时结果改变OD或接入边。
