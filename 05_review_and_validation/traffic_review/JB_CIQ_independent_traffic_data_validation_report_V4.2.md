# JB–CIQ交通数据独立核验与整改报告 V4.2

**结论：E01分组与描述统计通过，E01完整数据源质量为条件通过；E02道路通达性/旅行时间尚未完成。不能说所有交通数据处理已完成。**

## 数据与算法范围
- 源：五份PROVISIONAL_FCD 2026年5–9月CSV；冻结345节点分组CSV；V4.1派生统计及五组交通导出。
- 对账方法：逐行复读原CSV；以节点ID+时间戳+速度正规化值计算组级加密摘要多重集；每组复算有效记录、均值；验证日历与数值异常。
- 结果：345个节点×3672小时=1,266,840条；原CSV和五组拆分文件五组记录和值均一致；25个分组月度统计一致。
- 正速度1,141,555；空速度125,230；异常速度55。这里的有效仅指数字正且有限，不等于真实路况的物理有效性。

## 发现的重大问题
1. **9月weekday整月固定为6**：248,400行中215,280行错误。其他月份无此异常。用timestamp_local派生weekday字段，不应修改原始CSV；9月weekday列禁止参与工作日/周末分析。
2. **9月口径明显不同**：9月19列，对比5–8月28列；全部小时非空，但117,029行failed_request_count>0。这种字段不矛盾（小时内可同时成功和失败），但未证明观测质量相同；按原采集/聚合日志核验。
3. **9月长期恒速需复核**：54节点有≥24小时连续相同速度，最长节点R614、R615、R616在9月1日00:00至11日09:00保持106.0共250小时。其他月份也有短恒速现象，因此这是一项数据生成/聚合风险警示，并非数据造假的判决。完整236个区间在sept_long_constant_runs.csv。
4. **速度单位与交通语义**：CSV不保存TomTom API调用时的unit设置；原节点小时速度不等于路径级旅行时间；路径长度、方向和物流OD尚未具备。

## 数据准入建议
- 5–8月：可进入冻结速度描述分析；单位/路段几何来源仍待核验。
- 9月：可保留在档案和不涉及星期的原始速度描述中，但涉及月份差异、工作日与周末、道路运营异常的实证解释应先完成来源验证。
- E02：在有向路网边长度、边—交通点匹配、货运OD未具备前，不计算门到门旅行时间和无人机节时率。
- 不增设新实验；上述内容属于主实验前的**数据校验门槛**，其目的不是寻找有利结果。
