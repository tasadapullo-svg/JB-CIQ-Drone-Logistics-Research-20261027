## 2. 重大科学风险与本次查出的具体问题

### 2.1 旧 A 区编号复用导致订单坐标污染风险

历史 `19_site_reference_anchors_NOT_LAUNCH_PADS.csv`（Git blob `4c76d71d50cd48ba4a01ed902bd9e253fdef49cf`）含旧 A00–A08 与 B00–B09。比对结果：

- **10 个 B00–B09 同编号、同坐标**；只是几何地址一致，不能据此声明新道路和起降许可通过。
- **8 个旧 A01–A08 与新版同编号的地理坐标冲突**（不同的实际场所）。例如旧 A01 为 Johor Bahru City Square，新 A01 为 Swift Tebrau II；旧 A03（KSL City）在新网络中对应 A_N10 的同坐标位置。
- **旧 A00 在新网络中没有同 ID**，但与 `G_CIQ` 的坐标一致。

因此历史订单不能只凭旧 ID 接入新版 69 节点。必须原始订单坐标、OD 目的语义以及新需求生成逻辑逐项验证，并保留来源子集。

### 2.2 历史 ERA5 2 个网格不能假设覆盖所有 69 点的精确天气

历史 `CW_MY, CW_SG, SL_SG` 在 ERA5 均返回 1.50N、103.75E；`SL_MY` 返回 1.50N、103.50E。新节点到这两格最近距离中 **31/69 超过 10 km**，最远接近 20 km。这里的最近距离只是空间 QC，不能假设节点实测天气或局部阵风均相同，更不能产生逐节点独立观测的假象。建议以正式网格文件按节点空间位置重采样，保留源分辨率与代表性误差；无法补齐则进入不确定性情景，而不宣称实测风雨决定可飞率。

### 2.3 五个月 XLSX 原件存在明显版本差异

连接的 GitHub 目录列表中五个 XLSX 文件大小约 13.0–14.1 MB；同仓库 `final_verification_summary.json` 的历史校验文件大小约 1.03–1.51 MB。**同文件名不等于同字节版**；两套元数据不能相互代替。需要下载固定 GitHub 提交原件，计算 Git blob SHA-1、SHA-256、XLSX CRC、逐表行列及单位后，确定哪个是方法正式输入。不能将旧摘要的 SHA-256 当作当前版本通过。

### 2.4 有向道路与旧 37 条异常

GitHub 存在历史 A/B 两个 OSM 有向边 CSV（约 15 MB 和 8.7 MB），以及道路节点 CSV（约 3.2 MB 和 1.9 MB）；但这**不是新版 A/B/C 全覆盖且合法出入口已核实的道路图**。当前环境无法通过外部网络下载这些二进制与大型原件，因此未加载边集/节点集进行新版路由。旧 A 区 7 条 OD 必须重建语义，旧 B 区 30 条仍保持未修复。5 条 V3 地面交接线是直线关系，绝不能计为汽油车实际公里数。

### 2.5 原始订单总体缺口

历史 Stage 6 报告的 29,842 条合成订单是旧 A/B、5 个日期 × 30 种子的样本；源 CSV.gz 当前未取得二进制原件，不能独立逐订单审计。旧 V5.6 的 918,000 行是重抽样工程测试记录，且 V5.5 原冻结源和生成器缺失，不能与 29,842 条混合为新版 A/B/C 订单。**本次没有生成任何伪造的新版订单，也没有运营碳结果**。
