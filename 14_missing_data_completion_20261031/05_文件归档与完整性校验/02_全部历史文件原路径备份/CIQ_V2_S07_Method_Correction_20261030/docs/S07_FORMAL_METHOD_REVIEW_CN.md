## 1. 结论

## 4. 修正后的执行顺序（冻结前必须依次验收）

0. **源冻结**：保存 S06 V3 源哈希、69节点/116+5连接、历史 Git commit；建立只读 manifest。
1. **节点用途与空间交叉表**：单独创建 node_roles、node_geo_map、legacy_crosswalk、geo_eligibility；不要先生成订单。
2. **天气原件与小时日历**：取 2026-05-01～09-30 共153天=3672小时；按 UTC→Asia/Kuala_Lumpur(+08) 统一；降雨时段和wind FROM角度明确；天气代理分 ERA5/NASA/NEA，不跨源强行平均。
3. **OSM 有向道路基础图**：记录提取日期/范围/许可，接入 69 节点实际车辆入口，审核单行路/转向限制、孤立点和失败原因。
4. **交通速度映射**：在经过审计的方向道路上加载每小时速度或明确的 FCD 区域代理（另记证据级别、缺测）；为地面段建立动态路径查询接口，而非直线距离。
5. **合成任务总体二选一**：A) 严格复核老19点后沿用29,842订单（旧五日期的复现研究）；B) 新构造 A/B/C 订单（**新 population_id**，依据区域用途/需求分层并提供确定性生成器，不能冒充旧订单）。推荐主研究以 B 为新版主体、A 作为旧网对照，勿合并统计。
6. **任务校验与样本分层**：每单指定来源/目标的角色、国家、载重、体积(缺省标记)、释放/截止时间和 service_time；记录153日小时分层/抽样权重、种子；固定唯一任务主表，不按模式重复复制。
7. **建立可查询天气与道路时变输入**：S07 输出 time-indexed weather/traffic（及QA），S10 才根据真实模拟事件发车/起飞/返航时刻取样；同时记录天气预测/回看差异。
8. **同任务/可评价性检查**：所有模式引用同一 population+task_id，四种分母和独立失败原因；禁飞情景不等于取消任务，车辆回退另交调度器。
9. **发布双层 release**：`DATA_JOIN_PASS` 是源文件/主键/时间单位通过；`SCENARIO_SIMULATION_READY` 还需可行车辆 OD、机型模型与站点假设；`ACTUAL_DEPLOYMENT_APPROVAL` 与论文模拟分离。
