注：此表所有数值来自历史 QC JSON 的**已报告统计项**，本轮没有重新计算时序相关系数。ERA5 每月比主表多四行，历史 README 将其解释为返回/元数据附加行，并非额外独立的研究小时。

**NEA 细节：** 历史记录中，2026-05 对所列两项 NEA 站点/参考记录的核心指标报告了降雨 3.16%、风速 1.81%、风向 0.07% 的覆盖率。2026-06 至 09 月核心 NEA 指标的记录均为 `NOT_REQUESTED`。这不证明那些月份不存在可获得的真实观测，而是说明当前归档没有建立对应月份的完整 NEA 对照证据。

**气象判定：** 月表结构与来源文件检查 `anomaly_total=0` 是数据管道完整性的有用证据；它与雨量代表性、四点空间网格差异、源间一致性并非同一测试。低雨量相关性也不能单独据此断言某个数据源错误；应先核实时间分辨率、积算窗口、降雨定义、经纬度网格和极端降雨稀疏性。

## 4. Stage 6 历史逻辑迁移审查

| 原模型位置 | 已观察到的实现 | 新版处理规则 |

## 5. 新版模型数据接口（冻结候选，不是实测数据）

新实验统一采用 6 张逻辑输入表：

1. **空间节点表：** 可信的 `(zone,node_id)`、名称、WGS84 坐标、节点功能与审查状态，需可追溯至工程和图层 SHA256。
2. **候选地空连线表：** 有向端点与几何，保留 `screening_only`、空域和地块审查标记。
3. **同源合成任务表：** 固定 `task_id/seed/date`、起讫点、载重和时限；M0/M1/M2 使用完全一致的任务身份及明确的未评价订单分母。
4. **气象暴露表：** 来源类别、网格/站号、坐标、高度、SGT 时刻、风速风向、雨量、阵风和缺失原因；按实际起飞/返航时刻进行筛选。
5. **道路 OD 表：** 有向道路 OD、出发时刻、路线长度、交通状态、缺失/转向/国境/CIQ 等候范围。
6. **运营排放表：** 同一任务的地面燃料/电力、无人机用电、转运能耗和各自适用的排放因子；不重复计入同一车辆活动，运营与生命周期核算严格分离。

可执行字段清单见 `records/model_migration_contract_v1.json`。暂不定义 A/B/C 的物理边界，只允许由冻结 QGIS 工程和研究者签批确定。

## 6. 当前审计程序和测试

新文件 `scripts/stage03_source_gate.py` 使用 Python 标准库：

- 对用户本地完整仓库的天气 QC JSON、Stage 6 代码计算 **Git blob SHA-1 和 SHA256**；与本轮已读的固定 Git blob 对比。
- 仅在确实匹配后检查逐月天气摘要、NEA 状态和历史模型关键模式；绝不把缺失文件默认为 0。
- 读取 `07_stage02_spatial_gate.json`，但无法替代空间图层验收或签名。
- 输出 JSON 和 CSV；**无论源级检查结果如何，都不自动授权运行新一轮实验**。

实际执行证据：在当前无真实三分区工程和无本地历史原件的会话目录中，脚本返回退出码 `2`、状态 `HOLD_RECALC_BLOCKED`；五项合成单元测试全部通过。此测试通过仅证明程序自身的核心判断，不代表真实数据验收通过。
